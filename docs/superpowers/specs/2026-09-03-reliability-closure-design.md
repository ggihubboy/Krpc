# Krpc 可靠性闭环修复设计

## 目标

修复审计确认的核心正确性问题，并把 ZooKeeper 服务发现、失败换节点、过载保护、优雅退出、Demo 和压测变成可自动验证、可重复执行的交付物。

## 范围

1. ZooKeeper 句柄的访问和重建不能并发交叉。
2. 只有确认“请求尚未提交给连接”的连接失败才允许换一个节点；同步和异步调用遵守同一规则。
3. 服务端过载名额的检查和占用必须是一个原子操作。
4. 优雅退出同时观察业务任务和待发送响应，在宽限期内尽量完成响应。
5. 自动化环境负责启动、探活和清理 ZooKeeper 与两个服务实例。
6. Demo 缺少依赖或服务未就绪时必须明确失败，不留下容器和进程。
7. 压测输出记录日期、主机、CPU、RAM、内核、编译器、构建类型和完整命令。
8. CI 保留快速单测，并增加单独的 ZooKeeper 集成测试任务。

## 明确不做

- 不重放已经提交给 TCP 连接的请求，避免非幂等业务被执行两次。
- 不加入 TLS、鉴权、OpenTelemetry、业务 Fallback 或滑动窗口熔断。
- 不重写 Muduo、连接池或 ZooKeeper 客户端。
- 不把近似延迟桶改成精确直方图。

## 设计

### ZooKeeper 生命周期

增加独立的句柄互斥保护。所有读取、创建、安装 watch、重放以及 close/替换句柄的操作都通过同一保护边界，避免一个线程关闭句柄时另一个线程仍在调用 ZooKeeper C API。状态条件变量继续使用原有状态锁，避免把网络回调和状态等待锁成一个大临界区。

### 失败换节点

把“一次尝试结束”的结果统一为明确状态：已提交、发送前失败、已完成。发送前失败由调用协调层决定是否选择备选节点。同步调用等待最终结果；异步调用把后续尝试继续调度到 EventLoop，最终只调用一次 `done->Run()`。超时、服务端错误及发送后的断连仍不自动重放。

### 过载与退出

用原子 compare-exchange 预留任务名额，达到上限立即返回 `kRpcOverloaded`。响应提交给 EventLoop 前增加待发送计数，发送动作执行或因连接关闭放弃后减少计数。退出条件同时检查业务任务和待发送响应；宽限期到达时仍允许强制退出。

### 集成测试与脚本

公共 shell 辅助脚本检测 Compose V2 或 `docker-compose`，等待 ZooKeeper `ruok` 成功，启动服务后检查进程存活，并在退出时清理所有子进程和本次启动的容器。Smoke 测试执行 Login、32KB EchoBlob，并读取 ZooKeeper children 断言两个实例均已注册。

故障测试覆盖异步超时、过载和 SIGTERM 慢请求。依赖外部时序且无法稳定断言的场景不进入默认快速单测。

### CI 与文档

快速单测继续覆盖 Debug、Release、ASan。集成测试使用独立 Job，避免三套矩阵重复拉起 Docker。README 写清 Compose/netcat 等依赖、测试边界和执行命令；压测结果只记录本轮真实运行数据。

## 验收标准

- Debug、Release 和 ASan 构建测试通过。
- ZooKeeper 单实例 RPC smoke 和双实例发现断言通过。
- 异步发送前失败最终只回调一次，且最多尝试两个不同节点。
- 并发过载预留从不超过 `server_max_pending`。
- SIGTERM 测试在宽限期内收到完整响应，超时场景可按配置退出。
- Demo 成功与失败都能清理它启动的资源。
- CI 和 README 中的命令与本地脚本一致。
